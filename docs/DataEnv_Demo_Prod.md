# データ環境：本番（prod）とデモ（demo）

このアプリは **DB を1つだけ使い**、`data_env` 列の値で本番データとデモデータを論理的に分けています。

---

## 2つの環境の違い

| | prod（本番） | demo（デモ） |
|---|---|---|
| 用途 | 実際の人材・案件・提案履歴 | 営業デモ・検証用ダミーデータ |
| デフォルト | **常にこちら** | デモ機能オン時に選択可 |
| データの扱い | 本物データのみ表示・登録 | デモデータのみ表示・登録 |
| 切替方法 | デフォルト | `?demo=KEY` の URL を開く |

> **重要**：prod と demo は「論理分離」です。DB に直接 SQL を実行できる人はどちらのデータにも触れます。運用ルールで区別してください。

---

## デモ機能の切替方法

切替方法は 2 つあります（どちらでも同じ結果になります）。

### ① URL クエリで切り替える（初回・別ブラウザ用）

1. 以下の URL をブラウザで開く（`あなたの鍵` は `VITE_DEMO_KEY` の値）

   ```
   https://（アプリのURL）/?demo=あなたの鍵
   ```

2. 鍵が正しければ、ヘッダに **「本番相当 / デモ」の切替セレクト** が現れ、**デモが選択された状態**になる
3. URL から `?demo=...` は自動的に消える（アドレスバーに鍵が残らない）
4. もう一度同じ `?demo=あなたの鍵` の URL を開くとトグルでオフになり、**本番固定**に戻る
5. 鍵が間違っている場合は何も起きず、本番（prod）のみの動作

### ② 設定タブのトグルで切り替える（解除後・運用中）

`?demo=` で 1 度解除済みであれば、その後は **「設定」タブ → 開発者モード（デモ UI）** のトグルでオン / オフを切り替えられます（Phase 4.11 以降）。

```
設定 > 開発者モード > 「デモモード有効 / 無効（本番のみ）」トグル
```

このトグルは `localStorage.akinavi.demoUnlock.v1` を直接書き換え、URL クエリと同じ効果を持ちます。

### 切替状態の一覧

| 操作 | 結果 |
|---|---|
| 通常アクセス（`?demo=` なし・未解除） | 本番（prod）固定。切替 UI は非表示 |
| `?demo=正しい鍵`（解除前） | デモ機能オン。ヘッダ切替 UI が表示され、デモが選択される |
| `?demo=正しい鍵`（解除済み） | デモ機能オフに戻る。本番固定 |
| `?demo=間違った鍵` | 何も変わらない |
| 設定タブのトグル ON | デモ機能オン（ヘッダ切替 UI 表示） |
| 設定タブのトグル OFF | デモ機能オフ（本番固定） |

---

### 状態の保存場所

切替状態はブラウザの `localStorage` に保存されます。**別の PC・別ブラウザには引き継がれません。**

| 保存内容 | localStorage のキー |
|---|---|
| どちらの環境を選んでいるか | `akinavi.dataEnv.v1` |
| デモ UI を表示するかどうか | `akinavi.demoUnlock.v1` |

## デモ用サンプルデータの一括投入

デモ機能がオンであれば（**prod 選択中でも**）、「人材」「案件」タブ内に **デモシードパネル**（`DemoSeedPanel`）が表示されます（コミット `95120c1` で `demo` 縛りを解除）。
投入されるデータは常に `data_env = demo` のみで、**本番データには一切触れません。**

### デモ生成ボタン一覧（AI 不使用・ルールベース）

| ボタン | 内容 |
|---|---|
| 1 ペア生成 | テンプレと経験年数からエージェントメール体裁の本文を構築し、人材 + 案件をペアで投入。`inbound-email` regex が確実に拾えるフォーマット（`氏名 :` `最寄駅 :` `希望単価 :` `経験年数 : 約X年`）を使う |
| **本番→デモコピー（random）** | 本番から無作為に N 件の人材をコピーしてデモへ。`email` を `demo.prod+<uuid>@demo.invalid` に差し替え、`resume_url` / `box_url` を落として `drive_url` のみ保持 |
| **本番→デモコピー（recent）** | 本番の直近登録 N 件をコピーしてデモへ。営業デモで「最新の生データ感」を出したいときに便利 |
| **デモ人材メール再解析** | デモ環境内の `raw_profile.text` を持つ人材から N 件をランダム選択して `inbound-email` 再投入。スキル辞書を更新したあとの動作確認に活用 |

### マッチング検証用：スコア別 5 人生成（`DemoProjectCandidateGen`・コミット `060f0d7`）

選択中のデモ案件をベースに、**スコアの異なる 5 人**（90 / 70 / 50 / 30 / 10 pt 想定）を一気に生成します。

| 想定スコア | 構成 |
|---|---|
| 90pt | スキル満点 + 経験年数 7 年以上 + 単価範囲内 + 同じ都道府県 |
| 70pt | スキル一部欠け + 経験年数 5 年 + 単価範囲内 + 同じ都道府県 |
| 50pt | スキル一部欠け + 経験年数 5 年 + 単価範囲内 + **勤務地違い** |
| 30pt | スキル少しのみ + 経験年数 1 年 + 単価範囲内 + 勤務地違い |
| 10pt | スキル非該当 + 経験年数 1 年 + **予算超過** |

`calcRuleScore` の予想値を逆算しているので、UI のマッチング結果でも近いスコアが表示されます。マッチング・スコアの色分け（80以上 緑 / 60以上 黄）の動作確認に最適です。

## メール自動取り込みと prod / demo

Outlook からの自動取り込み（`poll-email` → `inbound-email`）は、**メールアカウントごとに保存先が決まっています。**

| メールアカウント | 保存先 |
|---|---|
| 本番用（human / project） | `prod` |
| デモ・開発用（human-dev / project-dev） | `demo` |

どのアカウントがどちらに対応するかは、Supabase Secrets の `GRAPH_REFRESH_TOKEN_*` と `poll-email` の設定で決まります（詳細は README.md の Secrets 一覧を参照）。

`inbound-email` を直接呼び出す場合は、リクエストの `data_env` パラメータで指定できます。

## よくある質問

**Q. `VITE_DEMO_KEY` を設定しないとどうなる？**

A. デモ切替 UI が実質使えません。常に本番（prod）のみの動作になります。

---

**Q. prod と demo で ID（UUID）は重複する？**

A. 重複しません。同じ人物を prod と demo の両方に登録した場合、DB 上は別の行・別の ID として2件存在します。

---

**Q. デモデータを本番に昇格させることはできる？**

A. 自動的にはできません。必要な場合は DB 上で `data_env` を `demo` から `prod` に手動で UPDATE してください。

---

**Q. セキュリティ上の注意は？**

A. `VITE_DEMO_KEY` は「デモ UI を表示するための共有秘密」程度の位置づけです。  
本番データを外部に絶対見せてはいけない要件がある場合は、ネットワーク制限や Supabase の別プロジェクト分離も検討してください。
