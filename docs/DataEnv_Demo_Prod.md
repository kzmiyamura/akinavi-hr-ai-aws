# データ環境「本番（prod）」と「デモ（demo）」について

このアプリでは、**データベースは1つ（同じ Supabase プロジェクト）**のまま、中身を **`prod`（本番相当）** と **`demo`（デモ用）** の2つに分けて扱います。

---

## 一言でいうと

- **prod**: 実運用の人材・案件・提案履歴が入る想定の環境です。
- **demo**: 営業デモや検証用のダミーデータだけを置き、**本番相当のデータと混ぜない**ための環境です。

データの違いは、テーブル上の **`data_env` という列**が `prod` か `demo` かで区別されています。アプリは「今どちらを見るか」を選ぶと、その値に一致する行だけを読み書きします。

---

## なぜ2つに分けるのか

| 目的 | 説明 |
|------|------|
| デモで消したくない本番データを守る | デモ用の登録・削除・マッチング試行を `demo` に閉じられる。 |
| 見せ方を切り替える | 営業デモではサンプルだけ見せ、通常利用では本番データだけ見せる。 |
| インフラを増やさない | DB を複製せず、1つの PostgreSQL で済む。 |

**注意**: `prod` / `demo` はあくまで**論理分離**です。DB に直接 SQL を流す権限がある人は、どちらの行も触れるので、運用ルールで区別してください。

---

## ブラウザでの見え方（画面の切り替え）

### 通常（デモ機能オフ）

- 画面上部の **「本番相当 / デモ」セレクトは出ません**。
- 参照・登録は基本的に **`prod` だけ**です（`localStorage` に前回の選択が残っていても、デモ未解除なら `demo` は使われません）。

### デモ機能をオンにする（共有用の「鍵」）

1. デプロイ時に **`VITE_DEMO_KEY`**（任意の秘密文字列）を環境変数に設定しておきます。
2. ブラウザで次のような URL を開きます（`あなたの鍵` は実際の値に置き換え）。

   `https://（アプリのURL）/?demo=あなたの鍵`

3. 鍵が正しいと、**デモ／本番を切り替える UI が表示**され、最初は **デモ（demo）** が選ばれた状態になります。
4. URL からは `?demo=` は消えます（アドレスバーに鍵が残り続けないようになっています）。

**鍵が間違っている場合**は何も起きず、引き続き本番相当のみの動きです。

### デモ機能をオフに戻す（トグル）

**すでにデモ機能がオンになっている状態で**、もう一度 **同じ正しい `?demo=鍵` 付き URL** を開くと、**デモ切替がオフ**になり、**本番（prod）固定**に戻ります。  
（同じブラウザでは `localStorage` に「解除済み／ロック」の状態が保存されます。）

### 状態の保存場所

- **どちらの環境を選んでいるか** → `localStorage`（キー名はコード内 `akinavi.dataEnv.v1`）
- **デモ UI を出すかどうか** → `localStorage`（`akinavi.demoUnlock.v1`）

別の PC・別ブラウザでは共有されません。デモ用 URL を渡すたびに、その端末で「鍵付き URL を開く」操作が必要です。

## メール自動取り込みと prod / demo

Outlook からの自動取り込み（`poll-email` → `inbound-email`）では、**メールアカウントごと**に次のように対応します。

| 想定 | 保存先の `data_env` |
|------|---------------------|
| 本番用の人材メール / 案件メール | `prod` |
| 開発・デモ用の人材メール / 案件メール | `demo` |

どのメールがどちらに入るかは、Supabase の Secrets にある **Graph 用リフレッシュトークン**（`GRAPH_REFRESH_TOKEN_HUMAN` など）と `poll-email` の設定で決まります。詳細は `README.md` の Secrets 一覧を参照してください。

Webhook から `inbound-email` を直接叩く場合は、リクエストの **`mode` / `data_env`** やクエリ・ヘッダで `prod` / `demo` を指定できます（仕様は `supabase/functions/inbound-email/index.ts` 先頭コメントが正）。

---

## デモ用の一括サンプル投入

デモ機能がオンで、かつ画面で **デモ（demo）** を選んでいるときだけ、**デモ用シード（ダミーデータ投入）パネル**が表示されます。  
投入されるデータは **`data_env = demo` のみ**で、本番相当の行には触れません。

---

## 開発者向けメモ

- 型定義・URL 鍵の扱い: `src/lib/dataEnv.ts`
- アプリ起動時の鍵トグル・`dataEnv` 状態: `src/App.tsx`
- DB クエリは原則 `.eq('data_env', dataEnv)` でフィルタ（`src/lib/db/*.ts` など）
- マイグレーションで列・CHECK 制約が入る: `supabase/migrations/add_data_env.sql`

## よくある質問

**Q. `VITE_DEMO_KEY` を設定していないと？**  
A. 正しい鍵の概念が無いため、**デモ切替 UI は実質使えません**（常に本番相当のみの動きに近いです）。

**Q. prod と demo で ID（UUID）は被る？**  
A. **別の行として別 ID** になります。同じ人物を prod と demo の両方に登録すると、DB 上は2行です。

**Q. セキュリティは？**  
A. 匿名キー（anon）と RLS の設計次第ですが、**デモ鍵は「UI を出すための共有秘密」**程度の位置づけです。本番データを絶対に見せたくない要件がある場合は、ネットワーク制限や別プロジェクトなども検討してください。
