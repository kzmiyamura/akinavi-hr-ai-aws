# Excel回帰テストの期待値について

## この文書の位置づけ

以前ここには期待値の一覧が手書きで貼られていたが、`--update-golden` で
`excel_golden.json` を再生成しても**この文書は更新されない**ため内容が古くなり、
JSON と食い違ったまま残っていた（2026-07-20 生成のまま、既に存在しないファイルを参照）。
実際に 2026-08-10 の調査でこの食い違いに惑わされたので、一覧の転記はやめる。

期待値の実体は `excel_golden.json` が唯一の正。確認はスクリプトで行う。

## 重要: これは「正解」ではなく「スナップショット」

`excel_golden.json` の `_verified` は **未確認** のままである。
中身は「その時点で抽出器が出した値」であって「経歴書の正しい読み取り」ではない。

この2つは別物で、前者を基準にすると**その時点で既にバグだった箇所は永久に検出されない**。
実際 2026-08-10 以前の golden には、案件表の列見出し「案件名」が 73ヶ月のスキルとして、
文の断片「WBSはエクセル」「コミュニケーションはTeams」がスキルとして固定されていた。

したがって現状の使い方は **回帰検出（変わったことを知る）** であって、
**精度保証（正しいことを知る）** ではない。後者が必要なら、人が経歴書を見て
確定した値を別に持つ必要がある。

## 確認のしかた

```bash
# 期待値に紛れ込んだ「スキルでないもの」「抽出ゼロ」「内部矛盾」を洗い出す
node scripts/audit_golden_junk.mjs

# 現在の抽出結果と期待値を突き合わせる
node scripts/test_excel_parsing.mjs --compact

# 抽出器を直したあとに期待値を貼り替える（＝現状を新しい基準にする）
node scripts/test_excel_parsing.mjs --update-golden
```

`--update-golden` は**現状を正しいことにする**操作なので、
抽出結果を目視で確認してから実行すること。

## 2026-08-10 時点の既知の問題

`node scripts/audit_golden_junk.mjs` で再現できる。

- **Y_O.xlsx**: スキル抽出ゼロ（総経験92ヶ月は取れている）。
  経歴書の上部に `#REF!` が多数あり、案件表の技術列が特定できていない
- **A_S.xlsx**: `Windows` `Linux` が 44ヶ月なのに総経験が 13ヶ月。
  スキル月数が総経験を超えており、どちらかが誤り。
  加えて `Winsdows`（原本のタイプミス）がそのままスキルになっている

いずれも「期待値として固定してよい値ではない」ため、
回帰の基準としては通っていても、精度としては未解決である。
